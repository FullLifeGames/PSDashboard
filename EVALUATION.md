# PS Dashboard Evaluation Reference

This file says what the engine claims, what it guesses, and where it fails. Read it before you trust or doubt a number. The score is a heuristic estimate for spotting swings and blunders, not an oracle. [ARCHITECTURE.md](./ARCHITECTURE.md) covers how the code is layered; [README.md](./README.md) covers setup and commands.

## 1. What the app knows about a game

### Sources

The loader takes a Pokemon Showdown replay URL or id, including smogtours ids and private `-…pw` password links, and falls back to the replay server's `.log` route when the JSON route is unusable. A locally saved replay loads too: drop a "Download replay" `.html` file or a raw protocol log on the loader, or use `Browse file`. `?replay=<id|url>` loads a replay on startup and `?embed=1` hides the app chrome for an iframe host (README, "Embedding").

### Revealed, sheet, guessed, manual

Every field of both teams carries its source, and the stats panel shows it:

- revealed: proven by the protocol (moves, items, abilities, levels, gender, Tera type), including ability reveals from effect attributions, item reveals from heal messages, mega stones, Life Orb recoil and Rocky Helmet chip, and a Heavy-Duty Boots inference for a Pokémon that takes no Stealth Rock damage,
- sheet: from an open team sheet (`|showteam|` or a "View team" chat export), authoritative for items, abilities, moves and EVs the protocol never showed,
- guessed: usage statistics and set assumptions; a spread fitted to observed damage shows as "fitted", a Choice Scarf the move order proved as "inferred",
- manual: your edits and imports.

Revealed and manual knowledge outrank the sheet, and the sheet outranks guesses. The simulator teams for branching and evaluation follow the same order, so a usage guess never overwrites a sheet item. Placeholders stand in for unrevealed Random Battle slots.

### Rule-outs

The protocol disproves guesses, and a guess never contradicts the replay:

- hazard, status, weather or Life Orb damage rules out Magic Guard,
- Stealth Rock chip rules out Heavy-Duty Boots,
- a landed Ground move rules out Levitate, but only inside the current move action, and never under Gravity, with an immunity-ignoring move, or from a species that can carry Mold Breaker,
- two distinct plain moves without switching rule out every Choice item (Dancer species excepted; called moves like Sleep Talk never count),
- a plain status move rules out Assault Vest,
- a Reflect, Light Screen or Aurora Veil that ends in the residual phase after the plain five turns rules out Light Clay for its setter, and one that ends after eight turns proves it. The turns come from the Dex condition (`conditionTurns` in [`dex-facts/screen-turns.ts`](./packages/replay-core/src/dex-facts/screen-turns.ts)); the log reader is [`inference/screen-evidence.ts`](./packages/replay-core/src/inference/screen-evidence.ts). A screen that an action removes (Brick Break, Defog) or that changes side unseen gives no verdict. Neither does a screen whose setter showed an item before, swapped it, may be an Illusion user, may have Klutz, or stood under Embargo or Magic Room. Generations 1 to 3 have no Light Clay and give none.
- a logged effect rules out the ability that would have refused it: a flinch, an unboost, a status or a volatile that lands on a body rules out each ability of its candidates that stops that effect from that source, and in doubles the partner's guard (Flower Veil, Sweet Veil) too. The reader asks the simulator on a twin battle of the game's generation, mod and game type ([`sim-ask/effect-refusal.ts`](./packages/replay-core/src/sim-ask/effect-refusal.ts), read by [`inference/blocked-effects.ts`](./packages/replay-core/src/inference/blocked-effects.ts)), so no ability list stands in the code; the Levitate rule above asks the same question. A line with an ability or item source and a source that may ignore abilities (Mold Breaker) give no verdict.
- a move's last PP spent with no berry line in the log rules out a Leppa Berry: a Toxic used to its maximum, Pressure's extra PP, a Revival Blessing used and offered again. `ppEaters` ([`inference/item-triggers.ts`](./packages/replay-core/src/inference/item-triggers.ts)) lists the items of the Dex that eat at 0 PP, and Klutz, Embargo, Magic Room, Unnerve, an Illusion team and a known or swapped item give no verdict.

A rule-out moves the guess to the next candidate instead of dropping to nothing.

### Usage and set guesses

Usage stats come from `data.pkmn.cc`, the only host that sends CORS headers, with the GitHub Pages mirror behind it when the primary host fails outright; a 404 counts as an answer. `@pkmn/smogon` supplies set assumptions for abilities, items, moves, natures and EVs. Guesses merge per species along a fallback chain: the format's own stats file, then the Smogon doubles ladder for VGC, the generation's OU, and Ubers. VGC reads the file of its year; Pokémon Champions VGC reads its own (`gen9championsvgc2026`), since Champions plays with megas, its own items and its own stat scale. A species missing from a file still gets guessed moves, items and abilities. Set assumptions come from the format's set file, then the generation's Ubers file (Doubles Ubers for doubles); VGC reads the set file of its year and never the Doubles OU analyses. Each guess names the file it came from. An ability no file can guess defaults to the species' slot-0 ability. When the set files cannot load at all, the top bar says "Smogon sets unavailable" instead of guessing without them.

A move the log shows books to the body that used it: a Pledge combination or Round books the shown move and not the partner's, and a body under Transform books its moves to the body it copied (`bookingIdent` in [`inference/client-facts.ts`](./packages/replay-core/src/inference/client-facts.ts)), so the copied body holds the moves its Ditto used. A corpus sweep holds every logged own move to the built set on every build path that has no manual edit; a pasted or edited set can lack a logged move, because a manual edit beats the sheet and the log.

A guessed set assembles as one unit. Published sets are scored against the revealed evidence, the winner fills the unrevealed slots, and pairwise vetoes trim the marginal fills: a big attack the set's boost does not serve falls (a Swords Dance Cobalion never guesses Body Press), an orphaned defense boost falls with its payoff, same-type redundancy collapses, and a Choice or Assault Vest guess suppresses guessed status moves. The stats panel and the simulator run the same guesser, and "Analyze game" waits for the Smogon fetches.

### Fitted spreads and inferred Scarf

Hidden EV spreads are fitted to the damage the replay showed. Every clean hit, in singles and doubles, becomes a damage observation; a deterministic solver checks standard spread candidates against `@smogon/calc` roll ranges. It replaces a usage-guessed spread only where at least two observations demand it, never touches revealed or edited spreads, and reads offense only from attacking observations and bulk only from defending ones. Speed comes from the replay's own races: same-turn move order and knock-outs landed before the victim acted become speed constraints. The parser drops any order something other than Speed explains (priority, Prankster, Quick Claw, Trick Room turns, weather speed abilities, copied actions). A knockout reads by the game's display bounds: the log shows the HP as a percentage that Scarlet/Violet rounds up and Pokémon Champions rounds down, as a 48-pixel bar, or exactly in a Custom Game ([`hp-display.ts`](./packages/replay-core/src/hp-display.ts)), so the least damage of a knockout is the lowest HP the shown text allows less the highest HP left, and no slack stands in for it. A knockout that no spread of the ladder reaches, with a guessed item, lets the solver try the usage-listed boost items in usage order and take the first whose fit reaches every knockout of the attacker with a lower total error ([`spreads/item-rung.ts`](./packages/replay-core/src/spreads/item-rung.ts)); the Item Clause and the teammates' known items bound the offers. Candidates respect the format's EV budget (508 total and 252 per stat; Pokémon Champions uses 66 Stat Points and 32 per stat).

A solve that misfits its own evidence falls back to the usage prior. Solved spreads reach every simulator team.

What the fit cannot prove: "the defender is bulkier" and "the attacker is weaker" fit the same damage line, so the solve guarantees consistency with the replay, not the true spread. A knock-out line is only a lower bound, so an attacker seen only in knock-outs keeps its guessed offense. A move order no legal spread reproduces keeps the guessed Speed.

A move order the mover cannot reach at full Speed reads as a Choice Scarf. The solver measures the mover against the slowest plausible opponent spread (common usage spreads, or the real one when a sheet or edit fixed it) and gives the Scarf only when even that opponent stays out of reach, the Scarf closes the gap, and the species runs Speed-invested spreads at all. The rule also runs backwards: a guessed Scarf that would outrun an observed order is dropped and the build takes the next item. Known items, sheet sets and protocol rule-outs stay untouched, and the sensitivity probes skip an inferred Scarf.

### Editing and importing sets

Edits for either player (`Edit Player` and `Edit Opp` in the top bar's `Setup` menu) rebuild the branch and replay its history. The editor offers legal pools: learnset-based moves, generation-legal items, the species' abilities, Tera types and natures. `Import/Export Sets` round-trips both teams as Showdown text (natures, IVs, levels included); imports persist per replay as manual knowledge. An import that names a move, ability, item, nature or Tera type the editor would not offer, or a species that is not on the team, imports nothing and lists what to fix. Hypothetical moves ("What if it had …") load into the set.

## 2. The evaluation

### Search modes

A sim-backed search plays every legal choice pair on forked battles and solves the choice matrix as a zero-sum game by regret matching. Sampling is deterministic with fixed seeds and KO-boundary roll grouping, and the work fans out over a worker pool sized by the machine's cores, so pool size moves only wall-clock. The engine selector offers four modes:

- depth 1 and depth 2: the full joint matrix, with deeper cells valued by a shallower sub-search,
- MCTS: a DUCT tree search (four trees of 600 iterations, each expansion drawing its dice from a seed hashed from the tree and the iteration; see "How the search prices chance"). A forced switch after a knock-out is a decision node inside the tree; the root matrix, verify sampler, play-outs and prover resolve replacements by the static pick. Chance-suspect root cells are re-verified by the matrix sampler, so a lucky miss in one tree cannot masquerade as a good line. A cell the trees played out over enough visits, with the trees in agreement, keeps the trees' value when it reads a decided game (±0.9). In an endgame of at most two living Pokémon a side it keeps any value once the trees visited the cell 100 times: there the trees play the game to its end, and the sampler's single ply turned the ranked lines against the score; a thinner pool stays with the sampler, which can see the win a short line hides,
- Auto, the default: singles run a depth-1 matrix with three samples while boards are full and the tree once a quarter of all Pokémon have fainted; doubles run the tree from the first turn. The team-preview lead stays on a depth-1 matrix in both game types.

Pivot moves (U-turn, Volt Switch, Flip Turn, Parting Shot, Baton Pass and the like) are move-plus-incoming pairs over the live bench, so the engine can say which Pokémon makes a pivot safe. Guaranteed-failing clicks are dropped from the candidates.

Tera enumeration is a setting. Auto infers "banned" from a replay that never terastallized; Revealed mode, the automatic behavior in draft and custom formats, restricts Tera to the Pokémon that terastallized in the replay.

Doubles search combined two-slot choices (per-slot targets, spread moves, one Tera, Mega Evolution or Ultra Burst per turn) over a candidate list cut down per side. Static threat hints rank the combos, distinct move cores fill the budget before gimmick variants, and the pair played in the real game always stays so its regret remains computable. A turn with a hidden slot action (a flinch, a fainted partner) is graded on the visible slot alone.

### How the search prices chance

An accuracy check, a kill roll and a secondary effect decide what a cell is worth, so the search names them and weighs them by the Dex chance. It does not trust how often five fixed seeds happen to hit.

- Root cells: a cell whose outcome hangs on one of those dice is priced as a mix of outcome classes. A class reads like `hit-nokill`, `hit-nokill+brn` (the burn came true), `miss` or `hit-kill`. Accuracy and kill odds come from `@smogon/calc` ([`ko-odds.ts`](./packages/eval-engine/src/ko-odds.ts)). The chance of a secondary comes from the simulator through the dice module ([`dice/secondaries.ts`](./packages/eval-engine/src/dice/secondaries.ts)), after the user's and the target's rules (Serene Grace, Sheer Force, Shield Dust, a King's Rock flinch). The search draws a class the seeds never reach by script, one draw per missing class (`forceMissingClasses` in [`search/cell-sampler.ts`](./packages/eval-engine/src/search/cell-sampler.ts), `forceMissing` in [`search/outcome-children.ts`](./packages/eval-engine/src/search/outcome-children.ts)); an effect under 1 % of the mass stays unpriced (`MIN_CLASS_MASS`). A flinch cuts the second mover inside its class, read from the Dex as a one-turn condition with a `BeforeMove` handler.
- Root quantiles: at a root cell tree k of four answers each named die with a quantile of its own ([`search/root-quantile.ts`](./packages/eval-engine/src/search/root-quantile.ts)). A die alone gets one tree in each quarter of its range, so a die of chance p comes true in floor(4p) or ceil(4p) of the four trees and a die of a quarter or more is never missed by all four; the order of the quarters differs from die to die, so two dice stay independent across the trees. The merge weighs each class by its Dex chance (`keyedCell` in [`search/merge-pool.ts`](./packages/eval-engine/src/search/merge-pool.ts)).
- Doubles trees: the root draw of each tree names its class through the pair plan ([`pair/tree-key.ts`](./packages/eval-engine/src/pair/tree-key.ts), `doublesRootChild` in [`search/expansion.ts`](./packages/eval-engine/src/search/expansion.ts)). The merge ([`mcts-merge.ts`](./packages/eval-engine/src/mcts-merge.ts)) prices each class with the trees that drew it and with its Dex weight. Singles trees book the same kind of key for their root cells.
- Below the root the tree stays flat: it holds no chance nodes (ADR 0023, which supersedes ADR 0009). The seed of an expansion is `treeSeed(iteration, seedOffset)` in [`search/leaf.ts`](./packages/eval-engine/src/search/leaf.ts), a hash of the tree's number and the iteration. The five fixed `SEARCH_SEEDS` are one arithmetic progression of the simulator's generator. Under them, at one draw index a 10 % effect came true in none or in a fifth of the five seeds, and in the singles tree one seed carried it in 74 % of its cells while the other four carried it in at most 2 %; a 90 % move missed in 73 % of the second seed's cells. With hashed seeds the pooled rate of each band with 150 or more events sits within 1.5 points of the Dex chance in the singles tree, Doubles OU and Champions VGC, and in VGC except accuracy 95 to 99 % (91.0 against 95.0 on 156 events), and two cells no longer share an outcome. Every other path reads the seeds of its own cell: the matrix, the verify round, the pair search, the trend probe and the endgame children take slot s of the cell's list (`cellSeed(s, key)` in [`search/leaf.ts`](./packages/eval-engine/src/search/leaf.ts), `key` the hash of the position and the two choices), so two cells never share one dice stream and the paths that read one cell share its list. On the old fixed list a 20 % secondary came true in 73 to 80 % of a singles matrix and a critical hit at 1.4 % against 4.2 %.
- The scripted dice that ask for a class name each draw by the simulator's own hook through `DrawNamer` ([`dice/namer.ts`](./packages/eval-engine/src/dice/namer.ts), ADR 0002). A paralysis, infatuation or confusion check is no longer read as the move's own accuracy or crit.

### Win probability

Choices rank by expected value against the opponent's equilibrium mix. The score lives in win-probability units: one sigmoid fitted to real outcomes applies at the search leaf, so averaging values averages probabilities, which makes variance worth something when you are behind. The mapping is phase-aware, claiming more per point of edge as Pokémon faint. Shown percentages pass a second calibration stage fitted on the weight corpus and checked out of sample, because averaging re-inflates the aggregated root score. A finished position reads 100/0.

### Matchup, hazard and race terms

- Matchup: a per-pair 1v1 threat estimate (movesets, type chart, stats, speed, big items, immunity abilities, priority, recovery walls) makes early positions readable before anything faints. Active pairs weigh more than bench pairs, and the term reads the doubled speed of a Tailwind side.
- Hazards: priced per living victim, with Boots, Magic Guard, grounding and Toxic Spikes immunity read from the simulator or the type chart. A living hazard remover holds an option on the net board (Defog nets relief minus the hazards it clears off its own side, and a net-negative option is never exercised). A benched Pokémon fights through its entry damage, and one that cannot survive re-entry is priced as finished unless a teammate can clear the hazards.
- Race: with one living Pokémon per side, the leaf gives the race winner 0.6 plus 0.1 per turn of clock margin, capped at 0.9. The clocks come from heal, residual and PP budgets, and mutual walls keep the static. Fixed-damage moves count at their fixed amount.
- Smaller terms: boosts that bite, coverage gaps, Choice items locked into bad moves, status-dampened setup, screens, speed control, and in doubles pair focus and redirection. A tie among the leading rows folds in the one-ply horizon trend.

### The forced-win prover

On a small board (at most three living Pokémon, or the last pair), or when the decided sweep names a side, a prover runs after the root search. It plays the favored side's moves against every reply in the simulator, outcome class by outcome class, until the game ends, and reports the proven mass: the share of classes along which the side wins against everything. A proof at or above one half lifts the score to that mass; the matrix and rankings stay as searched, and the engine's own score stays next to the bar. At 0.9 or above the turn card says "X wins in N against every reply", with a caveat when one roll stays open, a crit was not priced, or the rolls were sampled (doubles). The root tries the ranking's first three moves with the full proof, singles and doubles alike, and the budget is 100 matrix cells per position, never wall clock, so a position always proves the same way. A move that only stalls can spend those cells before the next move is tried; the ranking's first move is the search's best, so the corpus showed no proof lost that way. A class the simulator refuses stays open and lowers the mass. Each of the three root candidates runs a lazy pass first, which leaves the children that a die turned aside and so gives a lower bound of its mass; only a candidate at one half or more gets the full proof. A turn that draws one die more than once (a contact ability, a repeated Protect) or whose draws disagree on the faints is unpriced, and no proof runs through it; where the draws agree, the child carries the chance the simulator passes to its draw, so a repeated Protect splits its cell by the real chance. A proof below mass 1 stays visible from `MIN_FORCED_MASS`, for the side that lost its game too, and the card and the report name its share ("in 98% of the rolls"). A cell the class plan does not cover (every doubles cell, and a singles cell with a stalling move) draws the cell's own seeds and proves only when all draws agree: five in doubles, three in singles (`PLAIN_DRAWS` in [`endgame/children.ts`](./packages/eval-engine/src/endgame/children.ts)). A doubles proof that rested on three agreeing draws of a roll the simulator holds one time in three is gone with the fifth draw; the probe measured about one proof in five on the doubles holdouts. On boards above three Pokémon the prover waits for the search to read the game at 0.6 or beyond.

### Weight tables

Each rule set and game type reads its own static weight table, named from the replay's format ([`weights.ts`](./packages/eval-engine/src/score/weights.ts)). The fits use a pinned corpus of about 5,600 tournament and ladder games built the way the app builds teams, and the doubles and Champions fits are checked on a held-out third of their games.

- Standard singles: the hand-set table (matchup 120, screens 5, tailwind 8, Trick Room 10).
- Standard doubles (Doubles OU): fitted; screens 88, Tailwind 68, Trick Room 58, matchup 118.
- VGC doubles (Scarlet/Violet VGC): fitted on its own games; Tailwind 0, because the matchup term already reads the doubled speed, Trick Room 54, screens 48, matchup 169.
- Champions singles: a body counts 121 against 200 in standard singles, and a matchup 210 against 120.
- Champions doubles and Champions VGC: fitted on rated Champions games; screens 83, matchup 96, Trick Room 87.

### Other engines

The Evaluation panel can hand positions to another engine instead of the search ([ENGINES.md](./ENGINES.md)). The dashboard sends it the options the search would rank and checks the shape of every answer. An answer with the value of every pair goes through the same equilibrium solve as the search's matrix; an answer with one value per option stands as the engine gave it, so floors and punishers stay empty. Verdicts, the graph and the report read those values with the same bands. The bank, the holdouts and the expert pins measure the dashboard's own search, so another engine's percentages carry that engine's calibration; the panel says "estimate from" and the engine's name, and depth and samples hide while another engine evaluates.

## 3. Game analysis

### The three-pass sweep

`Analyze game` turns the game into an evaluation graph. A background sweep runs three passes: a depth-1 scan shapes the line in seconds, your settings then deepen every report-worthy swing, and the whole line converges to your settings. Per-turn d1, d2 and MCTS badges show where each turn stands. Results cache per turn in IndexedDB, merge across partial sweeps and serve single-position evaluations; a stored result never downgrades to a shallower one. The cache key carries an engine version, and any change that moves what a position evaluates to bumps it, so old results never pass as current.

The graph draws the win-probability line with markers on the turns whose play created each blunder-sized swing; clicking a point opens that turn. "Always on" starts the sweep when a replay loads and evaluates fresh variation positions without a button; it persists and is off by default. Turn 0 grades the team-preview decision: every lead (singles) or lead pair (doubles) is searched and shown as a diamond before turn 1. A turn the sweep has not reached offers "Analyze this position".

### Turn verdicts

Each turn shows what each player played against the engine's choice, with the regret and, from depth 2, the line that prevents it. The swing splits into a decision part and a chance part (rolls, crits). A plain-language sentence leads, then aligned worst-case rows for played against best.

Verdict bands sit on equilibrium-EV regret in win probability: inaccuracy at 5 points, mistake at 10, blunder at 20. Once a side stands at 85% or better, verdicts soften one tier, so garbage time does not stack blunders. Every flagged mistake or blunder is re-searched one depth deeper; the deeper look can acquit a move, never convict it. The re-search and the probes below run for every engine mode.

- Sacrifice: a faint from 15% HP or less is "a low-cost trade", softened one tier and shown as a gray chip. A healthy Pokémon switched in and fed is a simplification sack only while the engine's scores call the game decisively won on both sides of it. A Pokémon that stayed in and died above 15% is a deliberate feed only when the realized outcome hit the line's priced floor and its payoff inside the payoff window clears the safe guarantee. No label forgives a blunder-sized throw.
- Stay-in: a side KO'd before it acted is priced through a stand-in that chose some priority-0 move, so the turn grades the stay-in against the best escape. The order the log shows bounds that stand-in: a move that certainly stands ahead of an action before the fall would have run first, so it is out, and so is a switch (`ruledOutMoves` in [`branch/action-bound.ts`](./packages/eval-engine/src/branch/action-bound.ts), read from the simulator's priority and action speed; the bound abstains where the log's own order contradicts the queue). Sleep, flinch and full-paralysis turns keep a no-blame verdict.
- Risk: a flagged regret whose punisher the opponent never clicked is "risk (unpunished)", not a misplay.
- Read: an actual pair that beat the safe line's guarantee by a clear margin is a "read paid off", and its payoff may cash in over the following turns. The "safe" line is framed as a guarantee, not as "better".

Sensitivity probes check a surviving verdict against the opponent's next plausible items, rule-outs respected. If some item flips it, the verdict softens to the most charitable tier and says so ("hinges on Heatran's item (Choice Scarf: mistake · Leftovers: fine)"), because a grade that depends on hidden information is not a grade.

### The Read lens

A boundedly rational opponent model (softmax over the opponent's payoffs, anchored to the equilibrium mix, sharpened by the attack and switch tendencies seen in the replay) surfaces a "Read:" line when a confident prediction makes a non-equilibrium choice the better pick, with the payoff per predicted reply. The model is advice and never part of the grade, except that a flagged risk matching it becomes "a read against the opponent's tendencies".

### The game report

Once a sweep covers enough of the game, the report tells the story:

- who won and where the game tipped for good, naming the mechanism only when the report can vouch for it (a paid-off read, or a roll the protocol shows),
- a chess-style accuracy score per player, volatility-weighted, shown once enough decided turns exist,
- "the seeds of the loss": the loser's costliest choices before the tipping point (unpunished risks never count),
- the lead matchup as turn-0 chips, each side's biggest misplays and paid-off reads as clickable chips, and summed regret per player,
- net luck, with a decided game's resolution booked apart from luck,
- the denied early end when the protocol shows a side one roll from clearing everything left and the roll failing,
- the die behind the game's "biggest roll" (the report's own phrase): when the winner's sure kill under 100 % accuracy missed (singles), or a doubles click with a sure kill that names its move and target missed, one sentence gives both chances: "A hit would have left <winner> X% to win; after the miss <winner> stood at Y%." For X the engine searches a copy of the logged turn with that one die turned over (`rolledCopy` in [`branch/rolled-copy.ts`](./packages/eval-engine/src/branch/rolled-copy.ts)), at the setting of the next turn's card. Without the copy, singles say the miss and Y, and a doubles click stays silent, because the copy finds the die in the log ([`biggest-roll.ts`](./packages/eval-engine/src/biggest-roll.ts)),
- clickable key moments chosen by a turn's biggest component, so the die behind the biggest roll surfaces even when decision and chance partly cancel.

### Lines

A line is what the search expects after a choice: both players' choices for at most three turns, every die at its likeliest result, and the win chance for the player at its end. Under a turn's two "engine:" rows the Lines section shows, per player, the engine line (the engine's best choice, the opponent answering with the best reply of the merged ranking among those a tree holds a line against) and the played line (the choice made); a player who played the engine's choice gets one line. A doubles line shows one row per player and step.

- Where a line comes from. Each tree keeps the lines of every root row against its own top three rows of the other side (at most three lines a row, one per answer, the one against its top row first), as long as a node holds 8 visits and for 3 steps at most (`rowLines` in [`search/mcts-node.ts`](./packages/eval-engine/src/search/mcts-node.ts)). After the prover, the `lines` job replays the line on a battle ([`search/lines.ts`](./packages/eval-engine/src/search/lines.ts), the donors chosen in [`search/line-donors.ts`](./packages/eval-engine/src/search/line-donors.ts): every tree's lines of the row, the one whose first answer ranks highest in the merged ranking first, then the heavier first step) and plays each turn with every die at its likeliest result ([`dice/likeliest.ts`](./packages/eval-engine/src/dice/likeliest.ts)): a chance from one half up happens, a status check goes by its handler, a damage roll takes the middle step (8 of 16, 19 of 39 in Generations 1 and 2), a hit count the likeliest item of the sample, a pick the likeliest option. The job runs on its own worker message, reads no score and writes only the optional `EvalResult.lines`; a failed job leaves the result as it was. It costs 0.6 to 1.1 % of a tree search's CPU in the singles, Doubles OU and VGC samples (measured with one line a row; the walk now reads up to three cells a row and the replay still plays one line a request).
- What it shows. A tree search keeps a line only where a node holds 8 visits, so in the first sample a line that goes past the turn's own pair existed for 17 % of the best rows in singles and 35 % in Doubles OU; a line that ends where a player must choose who to send in says so ("the search made no choice there"). Only tree searches write lines: an early singles turn that runs the depth-1 matrix shows "No line on this turn", and a turn that another engine evaluated reads "No line: <engine> sends none."
- A row and a line are two numbers. A row's percentage averages many outcomes of its dice, a line follows one of them, and the lines' ends order the options the other way round from the rows' values on 9 of 19 sides in the singles sample. Neither is wrong; the line is one story the dice can tell, the row is the average over all of them. The Lines section prints both on each line ("row 23%, this line ends at 19%", the row being the engine's or the played one as the card prints it), and when any line ends at another number than its row, one muted sentence under the section says why: "A row's value averages every answer and die the search tried; a line follows one answer with each die at its likeliest result." The Game review's lines end with "ends at 19%" beside the row's value in the head, and the same sentence stands once under the review. A win-path line has no row, so it shows its end alone.
- The answer a line meets. The head of a line names the opponent's choice in the line's first step and its place in the merged ranking of the search that holds the lines: "vs Draining Kiss (Tzon's top choice)", "(Tzon's second choice in this search)", "(Tzon's choice 4 in this search)", or "(not among Tzon's ranked choices)" for a doubles pair that the ranking pruned. An answer below the top carries a title that says each tree follows the answer it explored most. The best answer means the best one overall by the merged ranking, never the one a single tree liked most. A line that opens with a replacement meets no answer and names none. The Game review's line text carries the same bracket after its first answer.
- The click. `▶ Play` turns the line into a variation: every step's slot choices carry their forced dice (the tooltip lists every one, a chip shows only a die that could have gone the other way), and Let it play out continues from the line's end with the simulator's own seed. A die the click cannot force (a sleep move's duration, a hit count with no range such as Population Bomb's) is named under the line. A variation that is open asks before the click replaces it.

### The Game review

Below the game report the Game review lists, per player, the turns that the cards grade as inaccuracy, mistake or blunder: the played value, the engine's value (or the safe line's, where the card compares against it), the loss in the card's words, and the engine line and the played line with a `▶ Play` each. A mistake that the card turns into a sacrifice or a read that paid off is not listed, and neither is an inaccuracy whose read paid off. The graph marks the same turns, a circle for player 1 and a square for player 2. A click on a row's turn opens the turn; with a variation on screen, "Back to the main line" leads out of it.

### Win paths in a lost endgame

A game that reached an endgame (three Pokémon or fewer standing in total, `ENDGAME_MAX_BODIES`; the count takes the bodies each side brought, so VGC counts four) adds an Endgame row to the Game review for the player who lost, and the card of every endgame turn asks "How could <player> have won from here?" for that player. A click starts the search from the endgame's first turn; the panel's picker moves it to a later endgame turn. The search is an on-request job, never part of a sweep, and it answers one step at a time ([`endgame/win-paths/`](./packages/eval-engine/src/endgame/win-paths/)). It reads a position the app rebuilds, so it needs the same sets as the card, and it writes into no result.

- Step 1, "A stronger play". The forced-win prover tries each of the loser's choices at the turn in the card's ranking, with three turns as its depth, and reports for each the share of the dice classes that win whatever the opponent answers. The panel shows the best choice's share beside the played choice's ("wins within 3 turns in 52 % of the dice whatever <opponent> plays. Played <choice>: 0 %."). A choice counts as stronger when its share beats the played one's and is above zero. The prover's caveats stand: a crit stays outside the share, and doubles prove over sampled rolls ("over sampled rolls" in the panel). The line is one witness: the likeliest dice under which the proof's choices win.
- Step 2, "Luck". Both sides play the engine's first choice, and a best-first search over the dice finds the likeliest sequence of dice under which the loser wins within three turns. The engine's first choice is the turn's ranking at the first turn and, at every later position, the best row of the one-turn matrix against the other side's equilibrium mix ([`endgame/win-paths/first-choice.ts`](./packages/eval-engine/src/endgame/win-paths/first-choice.ts)). The panel shows the dice as chips and the chance of that sequence ("This sequence: 10.8 %"). A sequence below 1 in 1,000 is not searched: "None within 3 turns at 1 in 1,000 or better." `▶ Play` forces those dice, so the variation ends in the win under any seed.
- Step 3, "A mistake by <opponent>". Both sides play the engine's first choice with every die at its likeliest result. At each turn of that line the opponent's lower-ranked choices are the candidates, tried mildest first (smallest loss against its first choice, then the earlier turn, then the better rank); the first one after which the loser wins within three turns is the answer ("If <opponent> had played <choice> (its 2nd choice) on turn N"), with the chance of the dice the line needs. A line allows one slip, and a replacement after a faint is never one.
- What the numbers mean. Each number is a lower bound. The stronger play's share is the prover's mass under its class model; the luck and mistake chances belong to the one sequence shown, so other sequences may add to the chance of winning. All three hold within three turns. A step stops at its search limit, counted and never timed so that it answers the same on every machine: 350 matrix cells or 175 simulator turns (`WIN_BUDGET` in [`endgame/win-paths/budget.ts`](./packages/eval-engine/src/endgame/win-paths/budget.ts)), about 10 to 20 s on the devbox where a step runs into it. A step that stopped says "Stopped at the search limit; nothing found so far." and one that covered every path says "None within 3 turns." In the probe over 54 lost endgames of the corpus, step 1 finished inside the limit on every singles, Champions OU, Doubles OU and VGC position and on 91 % of Champions VGC, and step 2 on 92 % of singles and 90 % of Champions OU and Doubles OU positions; step 3 was not probed on that corpus.

### How far one grade can be trusted

Two analyses of one turn with different search dice can give a side different tiers. Measured in round 89 on 63 sampled turns (122 sides, five dice salts per side, weighted to the population): the chance of another tier between two salts is 9.2 % on the round's base and 10.2 % at its head (pooled; singles 7.0 % to 9.3 %, doubles 19.6 % to 14.3 %). Among the sides that show a tier at the dice the app uses, the chance of another tier under another salt is 47 % (44 % on the base). The sample ran at the head of lane A's step A5f-4 (11.11.2026). One analysis is one draw of the dice. More draws for the graded side would lower the rate; that is a proposal with its cost in search time still to measure.

## 4. Timeline and playing lines

The replay is the main line. Executing a different move at any turn opens the single variation there, and the T0 view lets you pick leads (one per side in singles, both slots in doubles) and "Play from turn 0". Navigation is view-only and lossless. Playing a different move inside the variation cuts its tail; replacing the variation from the main line asks first. The graph overlays the variation as a gold curve. Branches save locally and share by link: a version 2 link carries a game's teams, seed and played choices and opens the game with its open variation at the sharer's turn (ADR 0014).

A new game is a main line of its own: `Game`, then `New game`, takes two teams and a format, opens at Team Preview (or at turn 0 where the format has none), and grows turn by turn as the user or the engine plays. Both sides know both teams in full, as with open team sheets, and the user plays both sides. The game is a record in the browser's storage (the format, both teams, the seed and every turn played), saved at Start and after every finished turn; the address names it (`?game=<id>`), so a reload opens it again. Its dice come from the game's seed, which the dialog shows and can set; a variation plays the game's own dice up to the change and what the seed gives after it. The app rebuilds the game's log from the record, so grading, the report, the lines and variations work as on a replay.

"Let it play out" has the engine play both sides' top choice to the end; Stop works anytime and every turn stays navigable. Clicking one engine line plays that turn out chess-style, the other side answers with its top reply, and the result re-evaluates. Mid-turn KOs resolve with the engine's replacement.

Bring-limited formats like VGC pick the bring-four at T0, and every reconstruction fields only what was brought. The brought bodies come from the log's `switch`, `drag` and `replace` lines, which also finds a body that entered and fainted within one turn. The trim is both sides or neither: if a side's list does not resolve, both teams stay whole. A side whose log shows fewer bodies than the bring count is a short side (a game that ended before its last brought body entered: 12 % of the corpus games in Scarlet/Violet VGC, 13 % in Champions VGC best of one, 18 % in best of three). The engine plays its fielded bodies plus one guess per missing body from the team preview, takes each set of guesses as a world, searches every world in full and blends the turn's score and each choice's value by the guess's usage share. It keeps the three likeliest worlds, which costs about 35 to 42 % more search time in the families with short sides (ADR 0024). A random format fills the missing bodies from its random-set data (`data.pkmn.cc/random`), six against six.

A deviation rebuilds the simulator at that point from the protocol, the team model, optional usage fallbacks, an HP and status correction at each turn boundary, and a forced turn. The dice the log names (misses, crits, hit counts, secondary and self effects, status checks, protect chains, speed ties) play as logged, and the dice it hides (damage rolls, sleep turns) come from a frozen seed (index 0 of the list, another seed of the list on a seeded turn). A turn whose faints still differ from the log's tries the damage-roll steps of the hits on those bodies, then seeds 1 to 15 for the dice no name covers. A turn that the simulator cannot play forced, or that would end a game the log goes on past, falls back to the search over sixteen seeds. When the guessed sets cannot replay a line (the simulated game wedges or ends early), the branch shows a divergence notice with a pointer to Edit Player/Opp.

The choices the rebuild replays are read from the protocol with these rules (round 89):

- A `|move|` line that another effect wrote (`[from]` Magic Bounce, Dancer, Magic Coat, Snatch) is not the body's own click, and a failed move whose target the log hides gets the aim that makes the simulator fail it as the log shows.
- The stand-in move of a body that never acts, or whose `|cant|` line stands before a logged action, follows the simulator's priority and action speed, so the turn keeps the log's order.
- A revive line answers with the body the log revives, and forced replacements fill the slots in the order the log shows, so a Ditto copies the foe it copied. A body that leaves the field by a correction keeps none of its volatiles.
- A choice the simulator would refuse (a move the rebuilt body lacks, a Disable or an Encore the request refuses) is replaced by a stand-in from the request, a move of the same kind, so the turn still plays.
- Each move slot carries the PP the log shows spent (`PokemonSnapshot.ppUsed`, read from the client's counts and set at every boundary), so a move at 0 PP never ranks first.
- A forme finds its slot by the name the simulator shows the log (Greninja-Bond, Rockruff-Dusk), no longer by a shared name prefix.

## 5. Measuring the engine

Adopting a weight, a search rule or a team-building change goes through a paired gate: the old and new engine run the same bank positions, and the verdict reads paired Brier and log-loss deltas with a 90% band from a bootstrap over replays, where pooled rows decide and single phase cells only warn. Weights also face the holdout. The commands below write only to gitignored folders.

- Bench: `EVAL_BENCH=1 npx vitest run --project eval-engine eval-bench` prints forward-model and search throughput to the console.
- Calibration bank: `node scripts/run-calibration.mjs [--slices 6] [--out .calibration/<name>]` runs [`test/regression/eval-calibration.spec.ts`](./test/regression/eval-calibration.spec.ts) (`EVAL_CALIBRATION=1`) in parallel slices over 130 pinned replays (Gen 9 OU, Doubles OU, VGC and a few drafts, tournament and ladder) and writes per-slice dumps, `merged.jsonl` and `summary.txt` there. It scores sign accuracy, confidence calibration, per-phase Brier and the win-probability fit, plus an `hq:` line (tournament and 1700+ ladder games) and a `luck-adjusted:` line. Levers include `EVAL_CALIBRATION_DEPTH`, `_MODE=mcts`, `_SAMPLES`, `_TRANCHE`, `_SMOGON=1` (usage fills, disk-pinned in `.smogon-cache/`) and `_SOURCE=fit|holdout` (the fit corpus or the holdout instead of the bank, which brings in Champions). The bank builds teams the way the app does. `node scripts/paired-calibration.mjs a.jsonl b.jsonl [--quality hq|std]` compares two dumps.
- Fit corpus and holdout: `node scripts/build-fit-corpus.mjs` pins about 5,600 replays in `test/regression/fixtures/fit-corpus-manifest.json` (logs cache in `.fit-corpus/`). `EVAL_FIT=1 npx vitest run test/regression/eval-fit.spec.ts` regresses feature weights per rule set and game type with cluster-bootstrap errors, folds clustered by player set, and a phase-conditioned win-probability fit; reports land in `.fit-corpus/`. A third of the doubles and Champions sets (`test/regression/fixtures/fit-holdout-manifest.json`) never enters a fit and serves as a test bed. The harness only reports; weights are adopted by hand after the paired gate.
- Endgame truth: a solver under `packages/eval-engine/src/endgame/` computes the exact value of endgames with at most three living Pokémon, singles and doubles, under best play, by recursing over turn boundaries with chance priced as outcome classes. A result is `exact` only when no cap (30 turns, 20,000 states, 120 s), unpriced chance or loop was touched. `EVAL_ENDGAME_TRUTH=1` grades the static, matrix and MCTS estimators against it on positions the bank exports (`EVAL_CALIBRATION_POSITIONS=<dir>`) and on synthetic fixtures; `node scripts/endgame-truth-table.mjs` renders the dump. The solver is an instrument, not a production path.
- Feedback drift suite: `npm run test:feedback` analyzes seven pinned replays (plus five census replays that feed `scripts/tier-census.mjs`) through the real app and grades them against a corpus distilled from an experienced player's review. It is on demand, hermetic (recorded replays and Smogon data), deterministic on one browser build, and warn-only: drift is an analysis point, never a failing test, and only harness breakage fails. It writes `docs/reports/feedback-drift.md` and `.json` locally (`docs/` is not in the repository); `FEEDBACK_DUMP=1` also writes the full dumps for a byte-level comparison. The report's alignment line says how many turns of each rebuild match the log (`perfect 37/38` for one replay) with the counts that miss it: `soft`, `faint-residual N`, `seeded N` (a turn that plays under a seed other than the first) and `fallback N` (a turn that took the sixteen-seed search); every count except `soft` shows only when above 0.

The always-on suites (`npm run test:regression` runs four Vitest projects: app, replay-core, eval-engine and ui) pin behavior and list themselves; README names the commands.

## 6. Known limits

The app does not recreate the original battle frame by frame, and branches can diverge from the replay when hidden information matters.

- Hidden moves, EVs, IVs, natures and some items and abilities are guesses when the replay did not reveal them. Some Tera details stay unknown before the reveal. Fitted spreads prove consistency with the replay, not the true spread (section 1).
- Usage guesses rest on `data.pkmn.cc` and its mirror. When neither has data for a format, set assumptions from `@pkmn/smogon` apply, then default simulator values. A Random Battle fills the bodies the log never showed from its random-set data (`data.pkmn.cc/random`); the unrevealed fields of the bodies it did show stay `unknown`.
- Choice reconstruction reads `|move|` and `|switch|` lines and translates doubles targets to simulator targets. Redirection, retargeting after a faint and phazing are covered, but unusual targeting effects and volatile state the snapshot never shows can still break or skew a reconstruction. HP and status are corrected at each turn boundary, yet other hidden or transient state may differ. An unplayable reconstruction is detected and reported.
- The rebuild forces the dice the log shows, among them every hit of a multi-accuracy chain such as Triple Axel's, the random target and the drag. Three kinds of result stay with the hidden dice: a proc the log shows (a burn from Flame Body, a Focus Band) can fail under the frozen seed, Present's power is a pick no die kind names, and Diamond Storm's self effect against two foes is not read from the log yet. A body the log knocked out where the simulator's damage roll leaves it standing is searched by the faint step; a turn that no step set and no seed repairs stays a named residual (the report's `faint-residual`). A knockout that only the simulator plays can leave the rebuilt side with more living bodies than the log shows until a snapshot corrects it.
- Chance in the search: Generations 1 and 2 have no class plan. A multi-hit move whose entry draws at every hit (Twineedle, Double Iron Bash), a random-target move in doubles, a self effect on a kill and a flinch pre-empted by another status in the same hit stay with the seeds. The merge trusts no class pool of a single tree, so a rare class that one tree played deep keeps the one-ply value of the verify round, even where that tree reads far from it. A rule that let a thin pool stand on its standard error was built in round 89 and reverted; the rule that decides when a single tree may stand is open work. A die of a quarter or more reaches at least one tree through the root quantiles; the pool of a class that a single tree played stays thin.
- Damage previews match the simulator's generation, sets and field, and apply an armed Tera toggle. Mega Evolution, Ultra Burst and Z-Moves are left out of previews until the turn executes.
- A share link of version 1 is a compact branch report (identity, format, players, branch turn, executed choices, final log) and does not replay an alternate line. A link of a game (version 2) does: the reader rebuilds the game on its own simulator from the teams and the seed and plays the entries, the open variation included. A link made on another simulator version can fail on a late entry, and the page names the turn.
- A line is one outcome of the dice. Its end value and a row's value can order the options differently ("Lines" in section 3), and a tree keeps a line only as deep as its nodes hold 8 visits.
- The engine is a heuristic: a score is not a proof outside the prover's budget, and a search with a fixed budget can miss a line a deeper one finds.
- The replay viewer, sprites and the viewer script load from Pokemon Showdown-hosted assets, and usage stats and set files need the network, so the app is not self-contained; a file-based replay still loads offline except for those assets. On phones the viewer keeps its desktop layout inside a horizontally scrollable container.
