# Architecture

This document explains how the code works: the layers, how a replay becomes teams and a live simulator position, how the evaluation engine is built, and how the app and the test suites are organised. [EVALUATION.md](./EVALUATION.md) covers what the engine computes for the user, the measurement tools and the single list of known limits. [README.md](./README.md) covers setup and commands.

The code has three layers. `@fulllifegames/replay-core` turns a replay into teams and snapshots and has no network and no DOM. `@fulllifegames/eval-engine` rebuilds positions in `@pkmn/sim` and evaluates them. The app in `src/` holds the React UI, the worker glue and the caches. Lint zones in [`eslint.zones.mjs`](./eslint.zones.mjs) keep the layers apart, so the direction of imports is a build error, not a convention.

## Layers and packages

| Path | Role | May import |
| --- | --- | --- |
| [`packages/replay-core/`](./packages/replay-core/) | Protocol parser, opponent inference, spread solver, team builder, Smogon lookups | `@pkmn/*`, `@smogon/calc` |
| [`packages/eval-engine/`](./packages/eval-engine/) | Branch reconstruction, forward model, static evaluation, search, analysis | replay-core by name |
| [`src/`](./src/) | Components, hooks, workers, app libraries | both packages by name |

The zones enforce four rules. A package never reaches `src/` or the UI layer. replay-core never imports the engine. The app imports the packages by name and never their files. Inside the app, nothing under `src/lib` imports hooks, components, `App` or workers, and components use the facade hooks (`useBranch`, `useEvaluation`, `useAppController`) instead of their internals. Package tests import their own sources relatively and the sibling package by name.

Package names resolve to the package sources through a Vite alias ([`vite.config.ts`](./vite.config.ts)), the tsconfig `paths` and the Vitest alias, so dev, HMR, the build and the suites share one module graph and no test reads a `dist/`. `tsc -b` builds each package as a composite project with its own declarations. Package sources import each other with `.ts` specifiers and compile with `rewriteRelativeImportExtensions`, so the emitted JavaScript runs in Node without a bundler. Each barrel (`src/index.ts`) is curated and pinned by [`test/regression/package-api.spec.ts`](./test/regression/package-api.spec.ts).

The app loads heavy parts on demand: reconstruction, the forward model, choice locks, damage previews, serialization, the protocol parser, the opponent inferrer, the team builder and hidden-power go through the re-export modules in [`src/lib/lazy/`](./src/lib/lazy/). A barrel imported both statically and dynamically would fold into the entry chunk, so the facades keep the lazy boundary where it is, and `sideEffects: false` lets the bundler drop unused re-exports. The simulator and the dex data stay out of the entry chunk.

## Replay to teams

**Loading.** [`ReplayLoader.tsx`](./src/components/ReplayLoader.tsx) accepts a replay URL or id, a dropped or picked file (a "Download replay" `.html` export or a raw log), and an optional pasted team. [`useReplay`](./src/hooks/useReplay.ts) fetches `replay.pokemonshowdown.com/<id>.json` and falls back to the `.log` route when the JSON answer is refused, empty, not JSON or has no log ([`replay-fetcher.ts`](./src/lib/replay-fetcher.ts)). A private replay's `-{password}pw` suffix stays on the fetched id and is stripped from everything derived from it. File exports go through [`replay-file.ts`](./src/lib/replay-file.ts), which unwraps the log from the export's script and reads the id from the hidden `replayid` input, never from the file name. [`useEmbedHost`](./src/hooks/useEmbedHost.ts) adds the host routes: `?replay=`, `?embed=1` and the `ps-load-replay` message (the messages are in the README).

**Snapshots and observations.** `parseReplayLog` ([`protocol-parser.ts`](./packages/replay-core/src/protocol-parser.ts), with [`protocol/`](./packages/replay-core/src/protocol/)) feeds the protocol to `@pkmn/client` and records a `TurnSnapshot` at each turn boundary: both sides' Pokémon, field, side conditions and the protocol chunk. The snapshots drive the turn slider and correct reconstructed state later. The same pass collects damage observations from clean hits (no crit, no multi-hit, no `[from]` attribution, inside the current move action) with attacker, defender, move, boosts, screens, weather and the observed HP fraction. Speed-order observations (same-turn move order, KO before acting) feed the spread solver as speed constraints.

**Team precedence.** `buildTeamsFromReplay` ([`team-builder.ts`](./packages/replay-core/src/team-builder.ts), [`team/set-resolvers.ts`](./packages/replay-core/src/team/set-resolvers.ts)) fills each set from the first source that knows:

1. what the replay revealed, plus the user's manual edits
2. the pasted team for `p1` and Open Team Sheets
3. fitted spreads: the solver in [`spreads/`](./packages/replay-core/src/spreads/) checks legal EV-spread candidates against `@smogon/calc` roll ranges for every observation a Pokémon appears in, fits only the dimensions the evidence measures, and falls back to the prior when the best candidate misfits. Candidates are legalized to the format's budget before scoring: 508 total and 252 per stat, or 66 and 32 Stat Points in Pokémon Champions formats (detected from the `|tier|` line, [`ev-budget.ts`](./packages/replay-core/src/spreads/ev-budget.ts)). The solve runs in the replay worker, once per knowledge state, after the Smogon data settles.
4. Smogon usage guesses ([`src/lib/smogon-stats.ts`](./src/lib/smogon-stats.ts), [`src/lib/smogon/`](./src/lib/smogon/)): the `hosts.ts` fetcher tries data.pkmn.cc and then its GitHub Pages mirror, and formats without a stats file fall back to the generation's OU file. [`set-coherence.ts`](./packages/replay-core/src/set-coherence.ts) assembles guessed moves as a coherent published set scored against the revealed evidence, then applies pairwise vetoes. The stats panel ([`team-info.ts`](./packages/replay-core/src/team-info.ts)) and the simulator's team builder run the same selection, so the display never shows a set the engine would not play.
5. `@pkmn/smogon` set assumptions ([`src/lib/smogon-sets.ts`](./src/lib/smogon-sets.ts)) for the remaining gaps

**Rule-outs.** Protocol evidence removes candidates before a guess survives (`RevealedPokemonInfo.ruledOut`): hazard, status or weather damage disproves Magic Guard, rocks chip disproves Heavy-Duty Boots, a landed Ground move disproves Levitate, two distinct plain moves disprove every Choice item, and a plain status move disproves Assault Vest. A disproven ability or item walks to the next candidate, and a disproven Choice guess stops fabricating move locks.

Teams export to and import from Showdown text ([`src/lib/sets-io.ts`](./src/lib/sets-io.ts)); imports overlay as manual knowledge, persist per replay id and rebuild a live branch through the same refresh path as team edits. The team editor draws from legal pools in [`src/lib/pokemon-options.ts`](./src/lib/pokemon-options.ts), loaded on demand.

## Branch reconstruction

[`branch-engine.ts`](./packages/eval-engine/src/branch-engine.ts) is the facade over [`branch/`](./packages/eval-engine/src/branch/), and [`useBranch`](./src/hooks/useBranch.ts) wraps it in React state. `startBranch` builds a `@pkmn/sim` battle, orders both teams so the replay lead comes first, sends `default` for team preview, splits the protocol into turn blocks and replays the original choices up to the target turn. Doubles state is slot-indexed (actives, moves, targets, switch lists, forced-switch flags, pending choices); the single-active fields still point at slot 0.

- **Lockstep replay.** A block's choices are written only when the simulator stands at that block's turn. A simulator that ran ahead skips stale blocks, one that fell behind advances on defaults first, and a wedged battle stops. Taunt-blocked moves replay from their `|cant|` line. Synthetic logs (missing `|upkeep|`, CRLF) are tolerated.
- **Boundary corrections.** At the target turn the snapshot corrects HP, status and the active Pokémon, including bodies the simulator fainted that the real battle kept. Each pass restores the side invariants the simulator relies on (`pokemonLeft`, `isActive`) and reruns the disable pass and the request rebuild. Protocol `switch` and `drag` lines fix the active slots when simulator randomness would phaze a different target.
- **Choice locks.** [`choice-lock.ts`](./packages/eval-engine/src/choice-lock.ts) stamps the locks the protocol proves (one distinct committed move on an undisturbed Choice item since the last real entry; a guessed item also needs the damage record not to contradict it). Corrected actives enter without inherited locks, and the stamp lands before the request refresh.
- **Hax alignment.** The simulator rolls its own RNG, so a phantom crit or miss can contaminate a turn. Before each block commits, [`hax-alignment.ts`](./packages/eval-engine/src/hax-alignment.ts) trials the block under 16 pinned seeds, scores the emitted events against the protocol block (game end and faint set first, then misses, crits, secondaries, hit counts, `|cant|` and move order) and calls `battle.resetRNG` with the best seed. The pick is deterministic. The trial runner is `trialAdvanceLog` in the forward model. Damage magnitude stays unscored because boundary snapshots already pin HP.
- **Turn-0 lead branch.** Target turn 0 rebuilds a fresh game to the start of turn 1 with the chosen leads first and no replayed blocks, corrections or locks. The lead decision is history entry 0 (`leadChoices`), and rebuilds of the variation re-seed it from that record.
- **Bring limits.** Bring-limited formats (VGC, BSS) run on a bring-all base format, so every reconstruction of such a replay passes `bringOnly` and trims the teams before the battle starts. `replayBringOnly` and `broughtSpeciesFor` ([`replay-format.ts`](./packages/replay-core/src/replay-format.ts)) derive the brought species from the protocol, one per body, and match them to built sets by exact name and then by unique base species. If either side's selection never fully entered the field, both sides stay untrimmed, because a pinned four against an unpinned six overrates the open side.

**Position source and replay worker.** Heavy replay work runs in a dedicated replay worker, a second instance of the worker script ([`client.ts`](./src/lib/replay-jobs/client.ts) with a job queue and abort-by-termination, [`handlers.ts`](./src/lib/replay-jobs/handlers.ts)), separate from the evaluation pool so cancelling an evaluation never kills a reconstruction. `startBranch` takes its runtime from the app's one position source ([`usePositionSource.ts`](./src/hooks/usePositionSource.ts)). The source answers from the exact-position store (a session cache keyed by replay, turn and sets) or asks the worker, which streams every healed boundary into the store. The arrival becomes the live runtime through `adoptSerializedRuntime` ([`branch/adopt.ts`](./packages/eval-engine/src/branch/adopt.ts)). Only a simulator that cannot start falls back to main-thread reconstruction. Evaluate, the dwell rebuild and the sweep share this source, so a position is reconstructed once per knowledge state.

## Evaluation engine

The engine lives in [`packages/eval-engine/src/`](./packages/eval-engine/src/) in five layers. The sim work stays off the main thread, and everything above it is pure and unit-testable.

1. **Forward model** ([`forward-model.ts`](./packages/eval-engine/src/forward-model.ts), [`forward/`](./packages/eval-engine/src/forward/)). It forks the serialized battle, enumerates legal choices (singles and combined doubles choices with targets, one Tera, Mega or Ultra Burst per side per turn, a `wait` sentinel for a side waiting out a forced switch), advances joint choice pairs under fixed seeds and resolves follow-up forced switches. Deserialization passes a repair layer. [`scripted-prng.ts`](./packages/eval-engine/src/forward/scripted-prng.ts) lets a caller script chance outcomes. The simulator speed layer in [`forward/sim-fast/`](./packages/eval-engine/src/forward/sim-fast/) (clone plan, handler dispatch, guard, rule table) makes forks cheap; the `EVAL_SIM_FAST` variable switches it (`0` off, `1` all levers, or a list of `rules`, `clone`, `dispatch`), and CI runs the engine suite with it off and on. Pokémon Champions battles run on the Champions mod of `@pkmn/mods`, which [`sim-mods.ts`](./packages/eval-engine/src/forward/sim-mods.ts) loads on demand for a Champions format only.
2. **Static evaluation** ([`eval-function.ts`](./packages/eval-engine/src/eval-function.ts), [`score/`](./packages/eval-engine/src/score/)). A fittable feature vector (bodies, HP, status, boosts, hazards, screens, speed control, an aggregated 1v1 matchup term with finite heal races, entry costs and stranded bench pieces, among others) times a weight table. `featureWeights(doubles, ruleset)` in [`score/weights.ts`](./packages/eval-engine/src/score/weights.ts) picks one of five tables: singles, Doubles OU, VGC doubles, Champions singles and Champions doubles. The `EVAL_FIT=1` harness fits them on the manifest-pinned corpus (about 5,600 games) with cluster-bootstrap errors, and a table changes only through the calibration gate. A phase-aware logistic maps scores to win probability once, at the search leaf ([`winprob.ts`](./packages/eval-engine/src/winprob.ts)), and `DISPLAY_K` is the second stage the displayed percentage passes through.
3. **Search** ([`search.ts`](./packages/eval-engine/src/search.ts), [`search/`](./packages/eval-engine/src/search/), [`mcts.ts`](./packages/eval-engine/src/mcts.ts), [`rank.ts`](./packages/eval-engine/src/rank.ts)). The matrix mode evaluates the joint choice matrix with iterative deepening and prunes dominated rows and columns, then solves it as a matrix game by regret matching. The tree mode runs DUCT Monte-Carlo trees (four seed-rotated trees, merged by [`mcts-merge.ts`](./packages/eval-engine/src/mcts-merge.ts)) and ranks the root with the same equilibrium solve. [`verify-select.ts`](./packages/eval-engine/src/verify-select.ts) picks the cells that the matrix-grade sampler re-prices before the solve. Boundary cells, where a priceable accuracy or KO-range roll decides the outcome, are priced as analytic mixtures of outcome classes ([`ko-odds.ts`](./packages/eval-engine/src/ko-odds.ts), [`cell-blend.ts`](./packages/eval-engine/src/cell-blend.ts), [`pair/`](./packages/eval-engine/src/pair/)). The Auto mode is a spec resolved per turn before dispatch from `SEARCH_BUDGET_DEFAULT` in [`search/budget.ts`](./packages/eval-engine/src/search/budget.ts): doubles run the tree from the first turn, singles run a depth-1 matrix until a quarter of the bodies have fainted (`AUTO_MCTS_FAINTED_FRACTION`) and the tree after that. Stored results carry the concrete engine that ran. The single builder from simulator bodies to `@smogon/calc` Pokémon lives in [`calc/`](./packages/eval-engine/src/calc/); the forced-win prover and the endgame solver are in [`endgame/`](./packages/eval-engine/src/endgame/) and [`search/forced-win.ts`](./packages/eval-engine/src/search/forced-win.ts).
4. **Orchestration** ([`orchestrator.ts`](./packages/eval-engine/src/orchestrator.ts), [`tree-orchestrator.ts`](./packages/eval-engine/src/tree-orchestrator.ts), [`worker-client.ts`](./src/lib/eval/worker-client.ts), [`eval-worker.ts`](./src/workers/eval-worker.ts)). A pure async orchestrator, with exact parity to the sync search, fans work out over a worker pool sized to the machine ([`pool-size.ts`](./src/lib/eval/pool-size.ts)). Workers post progress far faster than a panel can render, so [`throttle-latest.ts`](./src/lib/eval/throttle-latest.ts) collapses progress and partial results to the latest value per interval. Workers build as ES modules (`worker.format: 'es'`), and the replay-job handlers load as their own chunk so the pool's script stays small.
5. **Analysis** ([`played.ts`](./packages/eval-engine/src/played.ts), [`analysis.ts`](./packages/eval-engine/src/analysis.ts), [`turn-analysis/`](./packages/eval-engine/src/turn-analysis/), [`leads.ts`](./packages/eval-engine/src/leads.ts), [`opponent-model.ts`](./packages/eval-engine/src/opponent-model.ts), [`sensitivity.ts`](./packages/eval-engine/src/sensitivity.ts), [`summary.ts`](./packages/eval-engine/src/summary.ts), [`report.ts`](./packages/eval-engine/src/report.ts)). It reads the played actions from the protocol, matches them into the ranked lists, splits each swing into a decision part and a chance part, grades regret in win-probability units, and adds the verification, sacrifice, sensitivity and Read passes before the prose layer speaks. Narrative-only signals (streaks, decided-sweep stages, odds quotes) are computed at render time and never change a grade. [EVALUATION.md](./EVALUATION.md) describes the behaviour.

**Engine protocol** ([`engine-api/`](./packages/eval-engine/src/engine-api/)). Another engine answers `ps-dashboard-engine/1` over HTTP ([ENGINES.md](./ENGINES.md)). `buildEngineRequest` turns a serialized position and the options the dashboard ranks into a request (the spectator log, each side's request JSON, the full state), `validateEngineResponse` holds an answer to the protocol, and `engineResponseToResult` reads it through the ranking the own search uses (`rankFromMatrix`, `toResult`) when the answer carries a matrix. `checkEngine` runs the same checks against an endpoint for `npx @fulllifegames/eval-engine check-engine <url>` ([`bin/eval-engine.mjs`](./packages/eval-engine/bin/eval-engine.mjs), with the sample positions in [`samples/`](./packages/eval-engine/samples/)).

## App structure

[`App.tsx`](./src/App.tsx) composes the output of [`useAppController`](./src/hooks/useAppController.ts), which stacks four hooks in [`src/hooks/controller/`](./src/hooks/controller/) with explicit inputs: the replay context, the transient interaction state, the board (timeline pointer, deviation and rebuild, branch refresh) and the engine (position acquisition, evaluation view, the engine walk, the play-out loop).

**Unified timeline.** The replay is the main line, at most one variation exists, and a position pointer (`viewTurn` + `viewLine`) replaces any mode split. [`src/lib/timeline.ts`](./src/lib/timeline.ts) holds the pure model: position "turn T" means the state before turn T, and a deviation classifies as open, extend, truncate or replace. The chosen line is sticky until an explicit main-line click. `PSReplayFrame` shows the original replay for main-line positions and the branch log for variation positions; navigation sends one-shot seek requests, and a seek-intent guard stops a freshly remounted frame from knocking the chosen turn back with its boot echoes. `BranchPanel` renders at every position from the best available source: the live simulator at the variation tip, a recorded serialized position elsewhere in the variation, or snapshot plus guessed teams on main-line turns whose exact position is not yet known (upgraded in place once the position source delivers it). Every deviation funnels through one path: chess rules, then the proven rebuild, then the move.

**Replay frame.** The viewer iframe loads a generated blob document with `replay-embed.js` from play.pokemonshowdown.com. The iframe has no `sandbox` attribute: a same-origin blob document with `allow-scripts` can strip its own sandboxing, so the attribute bought console noise and no isolation. The app depends on Showdown-hosted scripts and sprites at run time and is not self-contained. On narrow screens the embed keeps its desktop layout inside a horizontally scrollable container with a 640 px minimum width.

**Evaluation hook and sweep.** [`useEvaluation.ts`](./src/hooks/useEvaluation.ts) drives [`src/hooks/evaluation/`](./src/hooks/evaluation/): preferences, the single-position path and the three-pass graph sweep (a depth-1 scan, then the configured settings on every report-worthy swing, then every remaining turn). Single results are tagged with the position they started at, so a run that finishes after the user navigated away renders as stale. Every position, in the sweep and in a single evaluation, comes from the boundary-corrected reconstruction through the position source. The sweep waits for the Smogon fetches so it never bakes teams without the guessed fills. Graph writes are monotone (`supersedesStored`): a shallower pass never overwrites a deeper stored turn, and across engines the configured engine decides.

**Eval cache and its version rule.** Results are cached in memory and in IndexedDB ([`src/lib/eval-cache-store.ts`](./src/lib/eval-cache-store.ts)). A key reads `v<N>|<cacheKey>|d<depth>s<samples>m<mode>t<tera>`, where the cache key carries the replay, turn and a sets fingerprint; a non-default search budget adds a tag to the version. `EVAL_ENGINE_CACHE_VERSION` in that file must be bumped in the same commit as any change to what a position evaluates to (rules, weights, search, reconstruction), so a stale result is never read as current.

Other app modules: `BranchSaveSharePanel` saves compact branch reports locally and builds URL-hash share payloads (they hold replay identity, branch choices and the final log, not a full deterministic restore); [`src/styles/`](./src/styles/) holds the stylesheet in domain files, audited for dead classes by `test/regression/css-audit.spec.ts`.

## Testing and build

[`vitest.config.ts`](./vitest.config.ts) defines four projects. `app` runs [`test/regression/`](./test/regression/) (app specs, integration specs, the API snapshot and the measurement chains). `replay-core` and `eval-engine` run each package's `test/` folder, white-box against `../src` (`npm test -w packages/<name>`). `ui` runs [`test/ui/`](./test/ui/), one spec per component and hook under jsdom with Testing Library (`npm run test:ui`). Root specs consume the packages by name over the barrels; only the calibration, fit, endgame-truth and speed-layer-setting specs read package internals. The browser suites stay on Playwright: [`test/e2e/`](./test/e2e/) (one file per theme), [`test/e2e-build/`](./test/e2e-build/) (production build smoke) and [`test/e2e-feedback/`](./test/e2e-feedback/) (on demand, `npm run test:feedback`: pinned and census replays swept through the real app, graded warn-only against expert truths, with the report written to `docs/reports/`, which stays local and untracked).

The measurement harnesses live in `test/regression/` and [`scripts/`](./scripts/): the calibration bank (`eval-calibration.spec.ts`, `bank-*.ts`, `run-calibration.mjs`, `paired-calibration.mjs`), the fit (`eval-fit.spec.ts`, `build-fit-corpus.mjs`), endgame truth (`endgame-truth.spec.ts`) and the engine bench (`packages/eval-engine/test/eval-bench.spec.ts`). EVALUATION.md lists their commands and environment variables.

[`.github/workflows/test.yml`](./.github/workflows/test.yml) has three jobs: the Node suites (with the eval-engine project run again under `EVAL_SIM_FAST=0` and `=1`), the browser flows and the production build smoke. `npm run pack:smoke` packs both packages, installs the tarballs into a throwaway project, runs the worked examples and type-checks a NodeNext consumer. `scripts/publish-packages.mjs` publishes the changed packages from `release.yml`. The `.github/workflows/pages.yml` workflow hosts the release channels.
