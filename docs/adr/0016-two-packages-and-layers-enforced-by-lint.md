# Two packages, not three, and the layer direction is a lint error

The code has three layers (AGENTS.md: ingestion and inference, deterministic reconstruction with `@pkmn/sim`, user interface): `@fulllifegames/replay-core` (replay log in, teams and snapshots out, no network, no DOM), `@fulllifegames/eval-engine` (rebuilds positions in `@pkmn/sim` and evaluates them) and the app in `src/` (React UI, workers, caches). The boundary began on 31.07.2026 as a hard rule for the engine: no imports from the branch engine, the protocol parser, React or the UI, and the whole input is a serialized battle plus settings, so the engine is testable headless, tunable without touching the app, and its forward model can be swapped. Of that rule only the layer direction below survives: eval-engine itself now imports replay-core and holds reconstruction. The split of 02.09.2026 made two npm workspaces and left the app at the root, which spared the Pages workflow, the Playwright configs and the Vite root. Reconstruction (`branch-engine`) sits in eval-engine, not in a third package: it depends on the engine (`serializeBattleStable`, choice items), and the engine's calibration uses reconstruction, so a third package would force a cycle. The direction is the import rule: a package never reaches `src/` or the UI layer, replay-core never imports the engine, the app imports the packages by name and never their files, `src/lib` never imports hooks, components or workers, and components use the facade hooks. These rules live in `eslint.zones.mjs`, so a wrong import fails the lint, which every push and the Pages workflow run. Package names resolve to the package sources through a Vite alias, the tsconfig `paths` and a Vitest alias, so dev, HMR, build and tests share one module graph and no test reads a `dist/`. Each barrel is curated, and an API snapshot test pins its exported names; a barrel change shows as a diff under `test/regression/fixtures/api/`. Package sources keep `.ts` import specifiers and the build rewrites them (`rewriteRelativeImportExtensions`); a rolldown library build was rejected because its declarations would carry extensionless specifiers that NodeNext consumers cannot resolve.

## Considered options

- Three packages (parsing, reconstruction, evaluation): rejected for the cycle above.
- One package: not recorded as considered; the aim of a second install ("parsing-only consumers get replay-core") is the only reason the sources give for the split.
- Layering by convention and review: replaced after round 25 by `no-restricted-imports` zones (phase 4 of the refactor spec): "from then on the layering is a lint error, not a convention".
- Moving the app into a workspace folder: rejected to avoid churn in deploy, test and Vite config.
- A Companion layout with `apps/*` and the dashboard under `/dashboard/`: designed on 04.09.2026 and never built (ADR 0021, proposed); AGENTS.md still describes `src/` at the root.

## Consequences

A rule that two layers share lives in one module and is imported (AGENTS.md); a deliberate copy needs a spec that compares both, because a package reaches the other only through its barrel. The three measurement chains (calibration, fit, endgame truth) and the speed-layer setting spec stay white-box, with named exceptions in the zones file. Each package owns its tests; specs that mix both stay at the root.
