# Formats that leave the app carry a version, and an optional field does not raise it

Three formats leave the app and meet a reader we do not control: the engine protocol (`ENGINE_PROTOCOL`, an HTTP contract with other people's engines), the state file of Report issue (`SUPPORT_STATE_VERSION`, read by whoever opens the issue) and the shared-branch link (`version` in the URL payload, read by the next version of the app, perhaps months later). Each carries its own version, and the rule is the same for all three (AGENTS.md, added in round 77, 28.10.2026): a change that breaks a reader on the other side raises the version, and the app keeps reading the old one; a new optional field keeps the version. Round 82 used the second half: forced dice travel in share links and support states as an optional field (ADR 0001), so neither `SUPPORT_STATE_VERSION` nor the link's `version` moved. The engine protocol goes further than the other two: its version is part of the request and response strings, the dashboard rejects an answer with another protocol string and shows the reason in the panel (today the validator accepts only `ENGINE_PROTOCOL`; a protocol 2 would ship with a reader for 1, `ENGINES.md`, Versions), and `check-engine` runs the same checks against an endpoint, so an engine author can test a build before a user adds it. An engine is an HTTP endpoint that the user's browser calls (CORS, https for hosted engines), and the result cache keys each engine's results by its id. The reason for HTTP from the browser, against a local process or a worker module, is not recorded in any source.

## Consequences

Old share links and support states keep working only as long as the reader keeps the old parser, and every version bump adds a parser to maintain. The packages' own exports are a fourth surface, guarded by the API snapshot (`test/regression/package-api.spec.ts`) and the package versions (see ADR 0017). The embed `postMessage` protocol of July 2026 (`ps-embed-ready`, `ps-load-replay`) carries no version; the sources do not say whether the rule is meant to cover it.
