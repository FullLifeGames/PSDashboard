# Every rule comes from the Dex of the game being played, and a lint rule bans the global Dex

The global `Dex` of `@pkmn/sim` is Generation 9 on Scarlet/Violet. It knows neither the type chart of Gens 1 to 5, a species' older stats and abilities, a move's older power, nor the Pokémon Champions mod (it changes moves, abilities, one item and three conditions; the counts move with each `@pkmn/mods` release). The census of round 67 counted 117 places that read the global Dex, and the lint rule of round 75 found 142 in 58 files, so a Gen 2 game and a Champions game ran on Scarlet/Violet rules wherever the code was careless. The decision (user gate 23.10.2026, "1a 2a 3a", with the note that the type chart and a species' abilities change between generations too): every read of a rule asks the battle's own `battle.dex`, or else one resolver, `rulesDex(gen, mod)`. Replay-core, eval-engine and the app read the global Dex nowhere else, and the lint rule `dex/no-global-dex-read` fails every read except the resolver's own file, with no per-field exceptions. One module decides what a Champions format is; every other place imports it. Every realm that rebuilds a game (main thread, worker, Node harness) loads the Champions mod itself before it asks the resolver, and a Champions game without the mod throws, because Scarlet/Violet would answer silently and wrongly. Our code translates and reads library data and never names a species or a move: a second lint rule (`names/no-new-dex-name`) counts Dex name literals per file against a baseline that only shrinks.

Champions sets stay on the Stat Points scale everywhere, the damage calculator included: it plays Champions as its own generation 0 (`@smogon/calc` 0.12, round 68), which dropped the EV = 8 * SP - 4 bridge of round 67. Converting to EVs for the simulator was rejected.

One exception holds on the hot path. A rule list that the search reads millions of times (the move's power at use, speed, the burn and poison residual) stays a hand table, and a sweep test holds it to the simulator across every Dex entry that can reach it. Asking the simulator there cost +22 % on the speed question against a 5 % gate (round 60); the move-power question cost 6 to 11 µs a call against 0.1 µs for the table, and the simulator switches Ability and Item off on the bench (round 57). Off the hot path, game questions go through one module (`sim-ask`) that asks a copy of the battle; it replaced hand lists and copies of a rule, the two causes of 12 of the 18 faults of round 70 (rounds 72 and 73). A speed tie asked of the simulator's queue costs about 18 µs a call against 1 µs for the hand rule; only the ladder with a per-position memo (a hit costs 0.02 µs) stays inside +5 % of tree time (round 72).

## Considered options

- A census spec of the remaining global reads, with exceptions per field (round 67): the lint rule replaces it, and the user ruled out exceptions.
- Hand tables for the differences (Champions powers, type charts per generation): the inventory of round 58 counted 61 duplicated rules and 57 rule faults among 184 hand-coded places. The principles of 02.10.2026 (rules from simulator and Dex, tests that check any rule we must know against the simulator, upstream reports instead of workarounds) settled on the library as the source.
- Reading the mod through `@pkmn/dex`: 19 files imported its `Dex`, which never sees the mod, because the host registers the mod on the simulator's Dex.

## Consequences

Round 75 moved the app's replay worker to load the mod (it did not before); `host-mod-order.spec.ts` (the hosts), `replay-jobs-mod.spec.ts` and `replay-jobs-mod-solve.spec.ts` (the worker) hold the order. A fix for a game rule starts with a sweep over every Dex entry of that kind, in every generation and mod the corpus plays. A Custom Game (draft leagues) keeps each species to its own abilities; only Hackmons formats are free (user gate 11.10.2026; the plan of round 60 had exempted Custom Games on 02.10.2026, and the gate reversed that). PP and heal fractions come live from the simulator, never from Dex base values.
