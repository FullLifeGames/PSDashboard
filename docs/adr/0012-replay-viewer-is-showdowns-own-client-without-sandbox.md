# The replay viewer is Showdown's own client in a blob iframe, with no sandbox attribute

The dashboard does not draw the battle. `PSReplayFrame` loads a generated blob document that pulls `replay-embed.js` from play.pokemonshowdown.com, so the app depends on Showdown-hosted scripts and sprites at run time and is not self-contained. The app once had its own scene (`BattleScene`, `BattleView`), a first draft that release 0.1.1 removed as dead code (commit e52c38d, 06.07.2026: "unused components from the abandoned earlier UI direction"). The reason to stay with Showdown's client is the user's, given at the gate of 03.11.2026: it is better this way, because it stays close to the original and is recognisable at once. The page owns the frame through a message protocol (`ps-turn`, `ps-seek-turn`, `ps-append-log`, `ps-replay-ready`): the original replay shows for main-line positions, and a variation shows its own log. The frame has no `sandbox` attribute. The July QA campaign (G24) had documented `allow-scripts` plus `allow-same-origin` as a deliberate trust boundary at `replay-embed.js`; the attribute was dropped after the July campaign (no round entry dates it), because a same-origin blob document with `allow-scripts` can strip its own sandboxing and Firefox warns about that combination, so the attribute bought console noise and no isolation. Showdown's script loader gives the page no help: it appends sixteen scripts without `async = false`, so they run in arrival order, and `battledata.js` reads `Config.routes` while it loads. The frame's own `Config` stub therefore carries Showdown's routes (`PS_CONFIG_DEFAULTS`), and the frame document orders the scripts itself (`EMBED_SCRIPT_ORDER_SCRIPT`). A change in Showdown's loader can break the frame; issue #96 (label `upstream`) tracks the loader issue.

## Considered options

- An own renderer of the battle: the early own scene was a first draft, removed as dead code; the user prefers the original (above).
- `sandbox="allow-scripts allow-same-origin"`: used first, removed as above.

## Consequences

The viewer follows Showdown's sprites, scripts and loader order. Showdown's client reads `BattleTeambuilderTable` for its per-generation Dex (`battledata.js`), so `teambuilder-tables.js` stays in the frame: without it a Champions replay falls back to base Generation 9 data and a Generation 8 replay throws in the tooltips (T318, round 85).
