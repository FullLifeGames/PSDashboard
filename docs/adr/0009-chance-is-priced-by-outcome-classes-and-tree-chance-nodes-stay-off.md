# Chance is priced by outcome classes at the cells, and chance nodes in the search tree stay built and switched off

Five fixed seeds can all hit at a true 43 % kill range, and a cell then reads as a certain kill: game 649664 turn 23 charged a 0.82-regret mistake to the winning Hydro Pump for that reason. Seed frequency is not probability. The engine handles chance in two ways. At the root cells it prices a boundary event (an accuracy or kill-roll cell) as a mixture of outcome classes, with the odds from `@smogon/calc` and the consequences of each class from the simulator (round 6, 16.08.2026, singles; fixed probe seeds fill empty classes). Doubles root cells (round 56, gate 23.09.2026) use a recording die that writes every hit and damage roll, turn each draw into a class and aim the next draw at the heaviest missing alternative; they cost 3.46x to 3.72x against a 4x gate, and a self-check falls back to plain seeds. In the tree, round 43 (12.09.2026) built chance nodes for the first two plies: a damage-roll or accuracy cell became a node with one child per outcome class, each class forced through the simulator's dice. The tree part lost on every measure that counts: the bank read +12 bp late (hq +15, luck-adjusted +11), the doubles tree cost 44 to 70 % more time, and the play-out pin flipped. A node that prices a side class sends the descents there in proportion to its odds, and late in the game depth is what finds the winning line. The user took the fallback at the gate (12.09.2026): `CHANCE_NODES = false` in `search/expansion.ts` keeps today's flat tree, whose root cells the cell sampler prices, while the outcome-class children (`classChildren` in `search/outcome-children.ts`) stay in service for the endgame solver and the forced-win prover (`endgame/children.ts`). The tree machinery and its tests (`eval-mcts-chance.spec.ts`) stay in the repository behind the switch, because a second attempt needs a new spec (main class deep, side classes static or one step) and not a rebuild.

Forced switches after a knock-out are decision nodes in the tree (round 42, user gate); the matrix, the verify sampler, the play-out and the prover resolve them greedily. The flag `FORCED_SWITCH_NODES` still reads `true`.

## Considered options

- Chance nodes on in plies 1 and 2 with a deficit pick: measured above, rejected.
- More seeds only: the doubles edge-cell error falls from 0.035 (4 seeds) to 0.024 (8) and 0.016 (16); the built class plan reached 0.021 at 4.5 draws per cell (round 56), a little worse than 16 seeds at about a quarter of the draws. Rejected for cost.
- Folding the order of events before the draw in doubles: a cell has up to four actors, redirection, retargeting after a knock-out and spread moves, so round 56 reads the classes from the dice log instead.
- Deleting the tree machinery: rejected, as the second attempt will start from it.
- Fixed seeds per class and an empirical doubles grouping with three seeds (`GROUP_SEEDS`): built in round 43 and switched off with the rest of the tree machinery.

## Consequences

Round 86 (T305, T323) built what this section named as open. The five fixed seeds of the first paragraph belong to the cell sampler and the other root-cell paths, and they stay. The tree's own draws below the root come from `treeSeed` (`search/leaf.ts`), a seed hashed from the tree's number and the iteration (T323, user gate 06.11.2026): the five seeds are one arithmetic progression of the simulator's generator, so at one draw index a 10 % effect had come true in none or in a fifth of the five seeds, and in the singles tree one seed carried it in 74 % of its cells while the other four carried it in at most 2 %; a 90 % move missed in 73 % of the second seed's cells. The sampler, the matrix search, the verify round and the endgame children keep `SEARCH_SEEDS`.

T305 added classes for secondary effects. A hit that does not kill splits by the entries of the move's `secondaries` that came true (`hit-nokill`, `hit-nokill+brn`), with weights from the chances the simulator gives through the dice module (`dice/secondaries.ts`: Serene Grace, Sheer Force, Shield Dust and a King's Rock flinch are read, not named). A draw says which entries came true from its dice record (`DiceSink`), not from a line of the log. A class the draws miss is forced by script, one draw per missing class and never a chase with probe seeds, which A3 estimated at 25 % more forks in the singles matrix. An effect under 1 % of the mass (`MIN_CLASS_MASS`) stays unpriced. Four live paths carry the classes: the matrix sampler (`search/cell-sampler.ts`), the class book of the tree's root cells (`singleChild` in `search/expansion.ts`), the doubles pair plan (`pair/pattern.ts`, `pair/sampler.ts`, `pair/log.ts`) and the endgame children (`classChildren` in `search/outcome-children.ts`). The tree's chance nodes (`groupedDraw` with `TREE_FORCED_CAP`) stay off, and a spec that turns them on states how it avoids the visit split that sank them.

Doubles trees key their root draws (user gate 05.11.2026). Each tree's root draw names its class through the pair plan (`pair/tree-key.ts`, `doublesRootChild`), and the merge prices each class with the trees that drew it and with its Dex weight. The cost was counted over the 36 searches of the bank's dispatch (10 singles matrix, 10 singles tree, 10 Doubles OU, 6 VGC) as clones of the simulator's speed layer against e7eef5e, the start of the round. With the extra time of the keyed draws counted as forks, the prototype read +4.1 % in Doubles OU and +7.9 % in VGC (the clones alone: -2.0 % and +0.7 %), singles trees unchanged by the keys. With the hashed seeds of T323 on top, the shipped state reads clones +11.5 % in Doubles OU, -5.5 % in VGC and -3.4 % in the singles tree (budget +20 %). The secondary classes themselves moved forks +4.9 % in the singles matrix and +0.7 % in the singles tree.

Rests: Generations 1 and 2 have no class plan (`boundaryEvent` returns null there); multi-hit moves that draw the entry at every hit (Twineedle, Double Iron Bash), random-target moves in doubles, a self effect on a kill and a flinch pre-empted by another status in the same hit stay with the seeds; the sub-search cells (`blendRoot` false) keep plain draws. The merge trusts no class pool of a single tree; the rule for when one tree may stand is open work (T322). The root and the tree price chance differently by design: a change to one must check the other.
