# Chance is priced by outcome classes at the cells, and chance nodes in the search tree stay built and switched off

Five fixed seeds can all hit at a true 43 % kill range, and a cell then reads as a certain kill: game 649664 turn 23 charged a 0.82-regret mistake to the winning Hydro Pump for that reason. Seed frequency is not probability. The engine handles chance in two ways. At the root cells it prices a boundary event (an accuracy or kill-roll cell) as a mixture of outcome classes, with the odds from `@smogon/calc` and the consequences of each class from the simulator (round 6, 16.08.2026, singles; fixed probe seeds fill empty classes). Doubles root cells (round 56, gate 23.09.2026, "1a 2a 3a") use a recording die that writes every hit and damage roll, turn each draw into a class and aim the next draw at the heaviest missing alternative; they cost 3.46x to 3.72x against a 4x gate, and a self-check falls back to plain seeds. In the tree, round 43 (12.09.2026) built chance nodes for the first two plies: a damage-roll or accuracy cell became a node with one child per outcome class, each class forced through the simulator's dice. The tree part lost on every measure that counts: the bank read +12 bp late (hq +15, luck-adjusted +11), the doubles tree cost 44 to 70 % more time, and the play-out pin flipped. A node that prices a side class sends the descents there in proportion to its odds, and late in the game depth is what finds the winning line. The user took the fallback at the gate ("machen wir so", 12.09.2026): `CHANCE_NODES = false` in `search/expansion.ts` keeps today's flat tree, whose root cells the cell sampler prices, while the outcome-class children (`classChildren` in `search/outcome-children.ts`) stay in service for the endgame solver and the forced-win prover (`endgame/children.ts`). The tree machinery and its tests (`eval-mcts-chance.spec.ts`) stay in the repository behind the switch, because a second attempt needs a new spec (main class deep, side classes static or one step) and not a rebuild.

Forced switches after a knock-out are decision nodes in the tree (round 42, user gate "übernehmen"); the matrix, the verify sampler, the play-out and the prover resolve them greedily. The flag `FORCED_SWITCH_NODES` still reads `true`.

## Considered options

- Chance nodes on in plies 1 and 2 with a deficit pick: measured above, rejected.
- More seeds only: the doubles edge-cell error falls from 0.035 (4 seeds) to 0.024 (8) and 0.016 (16); the built class plan reached 0.021 at 4.5 draws per cell (round 56), a little worse than 16 seeds at about a quarter of the draws. Rejected for cost.
- Folding the order of events before the draw in doubles: a cell has up to four actors, redirection, retargeting after a knock-out and spread moves, so round 56 reads the classes from the dice log instead.
- Deleting the tree machinery: rejected, as the second attempt will start from it.
- Fixed seeds per class and an empirical doubles grouping with three seeds (`GROUP_SEEDS`): built in round 43 and switched off with the rest of the tree machinery.

## Consequences

T305 (approved for round 86) adds classes for secondary effects (`docs/backlog.md`). The tree's chance-node path (`groupedDraw` with `TREE_FORCED_CAP`) runs only with `CHANCE_NODES` on, so T305's spec decides which live class path it widens: the root cell sampler, the class book of the tree's root cells, the doubles pair sampler or the endgame children. A spec that turns tree chance nodes back on states how it avoids the visit split that sank them. The root and the tree price chance differently by design: a change to one must check the other.
