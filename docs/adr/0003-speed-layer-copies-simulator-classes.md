# A speed layer copies the simulator's classes, so the simulator version is pinned to one release

The search spends most of its time inside `@pkmn/sim`: copying a battle took 35 to 53 % of a singles tree, and looking up effect handlers took 24 to 35 %. The engine package carries a layer that wraps the simulator at run time (`forward/sim-fast/`). It does not edit `node_modules` and does not fork the package. Three levers: one rule table per format instead of one per fork, a generated constructor and filler that copy a battle instead of a JSON round trip, and a pre-check that answers `runEvent` when no effect listens. The layer rebuilds the Pokémon closures from the simulator's source text, so it is only right for the version it was read against. A hash gate over the simulator functions it relies on (ESM and CJS builds) sets the status `hash-mismatch` and falls back to the standard path; a browser checks no hash. Every manifest that names `@pkmn/sim` or `@pkmn/mods` therefore pins it to one exact version (`test/regression/pkmn-pins.spec.ts`), `npm run upgrade:pkmn` moves the whole @pkmn train at once, and a simulator upgrade is its own change with every identity gate. An identity gate checks that a search with the layer on returns byte-identical results to the standard path: the guard spec with its census over Gens 1 to 9, byte-identical feedback runs, the bank. The layer is on by default; `EVAL_SIM_FAST=0` in Node and `'0'` in `localStorage` turn it off.

Why a runtime layer and not an edited `node_modules` (decision of 03.11.2026): an edit in `node_modules` holds in this repository only, while `@fulllifegames/eval-engine` is published on npm and its users install `@pkmn/sim` themselves. Only a layer that ships inside the package reaches them, and the hash gate lets it fall back on another simulator version.

## Considered options

- Search with the simulator as it ships: the baseline. The layer measured 2.35x (singles tree), 1.81x (doubles tree) and 2.39x (matrix) with every result byte-identical, and the whole analysis 1.45x faster. The round 58 study measured a fork copy at 683 to 87 µs and a handler pre-check at 5.76 to 1.05 µs.
- A patch file applied to `node_modules`: rejected for the reason above. Round 59 lists "no edit in `node_modules`" as a non-goal.
- Undo semantics on the simulator: the performance roadmap of 31.07.2026 judged that they cannot be retrofitted onto `@pkmn/sim`, because its mutations are pervasive. Round 58 measured a partial undo around `getDamage` at 180 µs per call and did not use it.
- `@pkmn/engine` as the fast backend: it covers Gens 1 and 2 only (`docs/completed/performance.md`, round 16). A poke-engine WASM port was rejected on 31.07.2026: own toolchain, a state translation layer, "historically our worst bug source".
- Rebuilding the Pokémon closures by hand per release: decision 3 of the round 59 design (user gate 24.09.2026 20:33) chose an automatic rebuild from the source text, with a self-test at first use and the status `fallback`, to keep upkeep low.

## Consequences

A library user cannot pull another simulator under the engine, because `peerDependencies` carry the exact version. Every upgrade pays for the identity gates: the step from 0.10.11 to 0.10.12 (round 78) moved six pins. Copies differ from a JSON round trip in keys that hold `undefined`, and that order reaches serialized states and the endgame solver's memo key, so only byte-equal children prove the layer right; the dynamic census exists because the bank plays only Gens 9 and 3. The layer builds functions at run time with `new Function`, so a future Content-Security-Policy without `unsafe-eval` would move it to `fallback`. T103 in `docs/backlog.md` lists the open gaps of the hash gate and the copy (helpers without a hash, nested `undefined` keys, a `check()` that is not exception-safe); its status line notes that no hash is checked in the browser. It is parked until the next `@pkmn/sim` upgrade (round 78 closed only what the 0.10.12 step needed).
