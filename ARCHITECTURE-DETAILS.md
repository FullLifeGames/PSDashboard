# Architecture details

This document holds the mechanisms behind [ARCHITECTURE.md](./ARCHITECTURE.md): the rules and traps of reconstruction, the engine's plumbing, the replay frame and the app's stores. Read it when you change reconstruction, the replay frame or the app's plumbing; ARCHITECTURE.md alone gives the layers and the data flow.

Each section carries the heading of the section it extends in ARCHITECTURE.md, in the same order.

## Replay to teams

**Header facts.** The header facts of a log (game type, generation, tier, the number brought at team preview) come from `@pkmn/client`'s `Battle` after it has read the header, the text before `|start` ([`replay-format.ts`](./packages/replay-core/src/replay-format.ts)). Only the four lines the facts come from go to the client, so the library's handlers decide what a line means (the last `|gametype|` wins, a `|teampreview|` without a number is six).

**Set files.** The fetch wrapper keeps the sets files a request parsed, because `@pkmn/smogon` flattens every move slot to its first option while the published file still holds them all ("Heat Wave / Hidden Power Ice" is one slot). A missing sets file (404) reads as an empty one before `json()` runs. The species of one request share one fetch and one parse per file, because `@pkmn/smogon` keeps a file only once its response arrived. A failed fetch is not kept.

**Team entry of a seen species.** `teamSpecies` ([`inference/lookup.ts`](./packages/replay-core/src/inference/lookup.ts)) maps a seen species to a team entry: its own name when the team holds it, else the held origin of a battle-only forme (Zygarde-Complete to Zygarde-10%), else the held entry of the same Dex number (Greninja-Ash from Greninja-Bond), else the forme's first origin. A battle-only forme never makes a seventh card.

**The carried pre-solve.** The base build's speed-only solve decides the items and the Speed the move orders asked for and builds both into its sets, so the full solve sees them as its prior. A mon the full solve forfeits (misfit damage) leaves its map, and the caller's build would reach past that prior to the usage guess, so `carryPreSolve` ([`team-builder.ts`](./packages/replay-core/src/team-builder.ts)) brings the pre-solve's entry back for it, with or without an item decision. A mon the full solve kept takes only the item decision and the Speed IV that the settling restored or lowered, because the full solve starts from those IVs; so does a forfeited mon whose max HP the log pinned. A mon that a pasted team or a team sheet matches is the exception: `buildSet` returns the sheet set before it reads `inferred`, so a carried entry reaches only the stats panel there.

## Branch reconstruction

**Rejected replay choices.** A replay choice the simulator rejects (a team edit can remove the move the protocol used) is answered for every side still without a choice with `default` ([`commitRejectedChoicesWithDefaults`](./packages/eval-engine/src/branch/runtime-session.ts)). A turn left half-chosen keeps the other side's accepted choice pending, and the next write would commit the turn with that stale choice, so the branch would play the user's choices one commit late. The snapshot corrections repair the aftermath.

**Boundary corrections** run four modules that keep the board where the game had it:

- `entry-effects.ts` plays the switch-in of every body the correction put on the field, through the simulator's own entry steps; the lines the entries write leave the log again (the block's alignment record reads that log afterwards). The board stands at the start of a turn, so what an entry sets for its own turn goes back to how the simulator's `endTurn` left it, a switch an entry effect asks for (an Eject Pack) included. A body the simulator already brought in during the block keeps the entry it played there. The same module plays the `|-start|` lines of the block that the board lacks, on the body standing on the line's slot at the block's end, through the simulator's own `addVolatile`, because the simulator's block misses one when it diverges. A token no condition names starts nothing, the lines before the block's residual round count one tick on a duration, a volatile the board has keeps its state, and a Protosynthesis-style stat takes the protocol's.
- `exit-volatiles.ts` keeps a body's volatiles as they stand when the Faint or SwitchOut event runs, before the simulator clears them, so an exit the game never saw (a knock-out the simulator's damage did not deal, a guessed Eject Button) leaves the body the game kept with its Protosynthesis, Quark Drive, Leech Seed, Heal Block or Substitute. The property serializes with the body, so a clone of the raw boundary carries it; nothing comes back when the log shows the body leave and return, or ends the effect.
- `held-items.ts` puts the items the protocol shows on the board, because the simulator plays every block with the build's guesses and its items drift. At each boundary a body the protocol shows an item line for takes that item, and a body without one gets its build item back when the simulator's own move or ability took it. A guess the simulator's own trigger consumed stays consumed, except on a body the simulator switched in and the game never did. A Sitrus Berry the simulator ate comes back when the HP the block shows, with no item line in the protocol, is one above the Dex's eating threshold; at or under it the game refutes the berry.
- `tera-restore.ts` restores the Terastallization marker, below.

**Faints and the bench.** What the protocol says about a side's bench steers the replacement round ([`branch/team-order.ts`](./packages/eval-engine/src/branch/team-order.ts)): `shown` holds the ids (name and base species) of every body its switch, drag, replace and detailschange lines name, `fainted` the slots the block's own lines faint, and `goesOn` whether the log plays on past the block. The game left a slot empty only where its body fainted, so a slot the simulator wants filled without a faint line is the simulator's divergence, not the bring list. When the game left a forced slot empty, the living bench bodies the protocol never shows were not brought: they leave the game as the simulator takes a fainted body out (no faint line, no fallen-ally count) and the slot takes `pass`. Nothing happens when the bench holds a shown body the log's answers leave over or a body that may disguise itself, and at the last block an empty slot proves nothing (a forfeit leaves it too).

**Terastallization after a revive.** The simulator deletes the `terastallized` marker in its faint block, so a body that faints only in the reconstruction (a guessed spread, a damage roll) and comes back through the HP correction has lost it while its side had already spent the Tera; a click the simulator swallowed (a locked move, Struggle) leaves the same hole. `restoreTeraFromSnapshot` ([`branch/tera-restore.ts`](./packages/eval-engine/src/branch/tera-restore.ts), Generation 9 only) restores it from the snapshot alone, which carries the marker per body at every boundary and drops it on a real faint (a body Revival Blessing brought back stays without it). The `|-terastallize|` line is no witness (it stands in the log long after the body fell), and "the side spent its Tera and nobody carries it" is no trigger. A living terastallized entry in the snapshot proves the side spent its Tera, so the side loses it first, whatever happens to the marker, so the search never offers a second Terastallization. The marker itself stays unset on a side with an Illusion holder, for an entry that matches no body or more than one, and for Ogerpon, Terapagos and Morpeko (`TERA_FORME_SPECIES`), and a side that already carries a marker is done.

**Forced choices.** In `forced-choice.ts` with `forward/request-reviving.ts`, a request marking a slot as reviving takes the fainted body the log's revive line names, else the first fainted body as the simulator's `default` does. A replacement request takes the entries of the log's next request, a revive line being no replacement, and the slots the log names take their bodies first, so a nameless slot never takes a body another slot names. The unclaimed entries fill the rest in log order, and an empty slot takes `pass` where the protocol's bench is out of bodies, else the first body no other answer took.

**Move types without a battle.** The quick picker has no battle at hand, so `snapshotMoveTypes` ([`branch/snapshot-move-types.ts`](./packages/eval-engine/src/branch/snapshot-move-types.ts)) types its moves on a throwaway battle of the snapshot body and asks as the live picker asks (`typeAtUse`, `typesUnderTera`): Weather Ball and Terrain Pulse need the field, and the -ate family, Liquid Voice and Normalize need the ability.

**The copy with the die turned over.** The copy plays the turn as the reconstruction does (the log's choices, seed index 0, every die the log shows forced, `faintStep`), turns the one die over before the play, and stops where the turn opens a replacement request, the next root. The faint step runs on the log's turn; the turned die plays on top of its result, and the faints may differ. A die the log does not show gives no copy. The hit's own damage roll, crit and secondary are no die of the log (it shows a miss), so they fall to the hidden dice of the seed, and no snapshot corrects the copy's position.

## Evaluation engine

**Canonical bench order.** The search sees every board with each side's bench sorted by species and nickname, the active slots staying ([`search/bench-order.ts`](./packages/eval-engine/src/search/bench-order.ts)), because the team-list order is no part of the game and yet a near tie falls to it (replacement hints are all 0 once the opposing active fell). Choices that leave the search are named back in the given board's slots, choices that enter it in the canonical slots, and move targets stay.

**The board key from the Dex: power handlers.** Moves that set their power when they land (by weight, HP, speed, status, the held item, happiness or the field) follow the same rule: the static asks the move's own handler in the simulator (`basePowerCallback`, the move's `onBasePower`, Endeavor's `damageCallback`) and keeps no rule of its own, only for handlers that are pure functions of the board. `test/power-handlers-census.spec.ts` names every other power handler of the Dex with the reason it stays out (it writes the battle, draws from the generator, writes the log, or reads the turn in progress) and checks each class against the simulator.

- In the `memo` class the answer reads only what `pairKey` keys (item, forme, happiness).
- In the `live` class it reads HP, status, the field, speed, weight or the history (fallen, hits taken), so `landedKey` keys the answer itself.
- In the `stages` class it reads the boost stages, which stay outside the memo key, so the memo prices the move at the power of no boosts and `boostedFraction` asks the power on the stages of the moment (`stagedPower`).

**Dice that one draw does not name.** A die with more than one draw, or a result the draw alone does not name, learns its raw answers on copies of the battle ([`dice/learn.ts`](./packages/eval-engine/src/dice/learn.ts)). The turn is played with raw answers for the die's draws and the result is read from the protocol, so the module keeps no threshold or formula. The hit count is a search over the die's draws in order, one draw deeper when the turn drew once more than the answers it was given (three draws at most). Effect Spore compares one number from 0 to 99 with its own thresholds, so its status is one draw whose results are runs of numbers, and the search bisects the range of the draw.

**The protector question.** The handlers of the Protect family (`shieldsFromHits`, `shieldsSide`) read the attack and ask the simulator whether a `HitProtect` handler of the field lets the hit through (`checkMoveBypassesProtect`); what they do to bodies is a write and never changes the return. So the answer is the same on every board where `findEventHandlers(source, 'HitProtect', target)` finds no handler, and [`sim-ask/protector.ts`](./packages/eval-engine/src/sim-ask/protector.ts) shares it across boards per Dex. A board with such a handler keeps the question on its own bodies. Whether a protector's condition stops an attack is the simulator's own `onTryHit`, run through `callHandler` on views, so it writes nothing the live battle can see: it returns nothing for a hit it lets through and `NOT_FAIL` for a hit it stops, and the punishing shields punish in this same handler, on the views. A handler that needs more than the views offer stops nothing. An attack that is its Dex move's plain copy keeps one answer per body pair, protector and attack; with the development check on (`askCheckOn`) every hit is asked again, so a battle mutated after its first question, or a shared answer that a board contradicts, fails loudly.

## App structure

**Variation turns.** One rule says which entries of a variation's history make a turn ([`src/lib/variation-turns.ts`](./src/lib/variation-turns.ts)), so every reader names the same turn. An entry is an interlude, a replacement between two turns, when it is of kind `forced` (one side replaces) or carries the `turnNumber` of the entry before it, the shape in which older state files, saved branches and share links hold a replacement on both sides (ADR 0014).

**Replay frame layout.** Showdown's embed lays the battle out at 640 px (642 with its border) with the log beside it, so a narrower frame would cut the opponent's side, the log and the Music control. The replay document ([`src/lib/replay-phone.ts`](./src/lib/replay-phone.ts)) decides by its own width, and the app follows its height with `followContentHeight` (`replay-frame-height.ts`). The scale is the frame's width over the battle's border box (642 px), with no inset. `Battle.onResize` (`battle.js`, `autoresize` on) writes an inline `transform: scale(width / 640)` and `margin-bottom` on the battle frame whenever the window is under 640 px, and an inline style beats a plain rule, so the two declarations for the transform and the margin carry `!important` and the document's own `--ps-k` decides.

**App size.** The app's size is one store that `main.tsx` starts once ([`src/lib/ui-scale-store.ts`](./src/lib/ui-scale-store.ts)). It reads the setting and the window, writes the factor onto the root element as `--ps-scale` (`base.css` turns it into the root's `zoom` and divides the `vh` and `vw` rules by it) and follows the window with a resize listener, so no React state decides the size. Components read it through `useUiScale`. The window is the real one: `innerWidth` and `innerHeight` are in CSS pixels of the browser's own zoom and never see the root's `zoom`, so the rule never doubles a browser zoom already set.

**The share link of a game** (version 2, [`src/lib/new-game/share.ts`](./src/lib/new-game/share.ts)) holds the format, both teams as `Teams.pack` text, the seed, the leads and every choice; the log, the positions and the header stay out. [`hooks/branch/share-open.ts`](./src/hooks/branch/share-open.ts) starts the format's battle on the seed and plays the entries. A slot choice is one string where it can be: a move is its name, `@<target>` when it has one and `#<modifier>` when it carries one (`Close Combat@1#terastallize`; the modifiers are `terastallize`, `mega`, `zmove` and `ultra`), and a switch is `>` and the Pokémon's name (`>Rotom-Wash`). A choice that carries forced dice, a move whose name does not spell its id and a switch whose name is a nickname stay as the object the app holds. An entry is a pair of the two sides' slot lists (a turn), a side and its slots (a forced replacement) or `L` with the two lead lists (the lead entry of turn 0, with a trailing `1` where the lists are the whole brought selection).
